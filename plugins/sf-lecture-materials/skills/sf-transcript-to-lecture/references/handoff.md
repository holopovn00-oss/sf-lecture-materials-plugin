# Контракт передачи полного текста

Используется существующая форма SF `LectureText` 2.0.0. [Исходная JSON Schema](lecture-text.schema.json) поставляется для справки; вспомогательный скрипт дополнительно проверяет связи и покрытие. Отдельный формат [проверки комплекта](package-checks.md) задаёт сопровождающий `text-review.json` для команды `check-package`; схема LectureText и вход `draft.json` не меняются. Это не публичный API контроллера SF: совместимый файл не означает возможность отдельно запустить его внутренний этап.

## Исходные блоки

`source-blocks.json` — JSON-массив блоков в исходном порядке:

```json
[
  {
    "source_block_id": "source-001",
    "text": "Обычно около 15%, если спрос не падает.",
    "substantive": true,
    "source_uri": "C:/Lecture/transcript.srt",
    "start_ms": 1000,
    "end_ms": 8000,
    "page": null,
    "slide": null,
    "locator": "cue 1"
  }
]
```

Пример демонстрирует форму; не копируй его содержание в другую лекцию. `page` и `slide` считаются с 1; время — миллисекунды исходного файла, с 0. Неизвестные поля — `null`. Сохраняй исходный текст полностью, не извлекай только первые строки. Опись `source-manifest.json` отдельно фиксирует исходные файлы, их SHA-256, порядок и способ чтения. Хеш массива извлечённых блоков не заменяет хеш файла.

## Редакторский результат до сборки

`draft.json` имеет ровно пять полей: `folder_id`, `title`, `blocks`, `transformation_ledger`, `structure`.

```json
{
  "folder_id": "lecture-001",
  "title": "Название, указанное пользователем",
  "blocks": [
    {
      "text_block_id": "text-001",
      "text": "Обычно около 15%, если спрос не падает.",
      "source_block_ids": ["source-001"],
      "perspective": "lecturer_direct"
    }
  ],
  "transformation_ledger": [],
  "structure": {
    "sections": [{"section_id": "section-001", "number": "1", "title": "Условия оценки"}],
    "topics": [{"topic_id": "topic-001", "section_id": "section-001", "title": "Зависимость от спроса"}],
    "placements": [{"text_block_id": "text-001", "section_id": "section-001", "topic_id": "topic-001"}]
  }
}
```

Помощник дополняет только структурные значения по умолчанию: роль `paragraph`, `keep_together=false`, неизвестные дополнительные поля `null`. Он не редактирует текст, заголовки и таймкоды. Допустимые текстовые роли также включают `callout` и `summary`, но роль `summary` не разрешает сочинять отсутствующий в источнике итог. Группы разделов и тем непрерывны и идут в объявленном порядке.

Для удалённого несодержательного исходного блока добавь одну запись:

```json
{"source_block_id":"source-noise-001","disposition":"removed_nonsemantic","reason":"Проверка микрофона перед началом лекции"}
```

Этот ID должен существовать в источнике и иметь обоснованное `substantive=false`. Нельзя одновременно удалить и включить один блок. Соседние исходные блоки одной подтемы можно объединить в один итоговый, сохранив все ID в порядке источника. Основной текст подтемы оформляй без внутренних абзацев и принудительных переводов строк: предложения соединяются пробелом. Не дублируй исходный ID в нескольких итоговых блоках. Исходные границы и локальные таймкоды сохраняются в `source_block_ids` и `source_locators`, а не как обязательные печатные разрывы.

`transformation_ledger` предназначен для учёта удалённого технического шума. Решения о замене слов, сохранении спорного написания, подписи или заголовка веди отдельно в `text-review.md`; не добавляй их в этот массив. При объединении соседних блоков сохраняй все `source_block_ids` в порядке источника. Несколько локальных шкал остаются отдельными `source_locators`, без придуманного суммарного диапазона.

## Сборка и проверка

Команды выполняются из папки навыка; пути примера замени на реальные пути задачи. Достаточно Python 3.11+ без сторонних пакетов:

```powershell
python scripts/handoff.py build --sources 'C:/Task/source-blocks.json' --draft 'C:/Task/draft.json' --out 'C:/Task/text-result-v1'
python scripts/handoff.py check --sources 'C:/Task/text-result-v1/source-blocks.json' --lecture 'C:/Task/text-result-v1/lecture-text.json'
python scripts/handoff.py check-package --review 'C:/Task/text-result-v1/text-review.json'
```

`build` создаёт только новую папку и отказывается перезаписывать существующую. Он сохраняет нормализованные исходные блоки, полный JSON и программно полученный Markdown. `source-manifest.json`, `text-review.md` и `text-review.json` подготовь отдельно после сборки. Команда `check-package` проверяет их связи и хеши, но не создаёт и не редактирует отчёты. Поля `source_blocks_hash`, `source_locators`, `assertions` и `content_hash` вычисляются, а не придумываются моделью. Канонизация: JSON UTF-8, `ensure_ascii=false`, сортировка ключей, разделители `,` и `:`, SHA-256 в верхнем регистре. `content_hash` считается по объекту без самого этого поля; он отличается по назначению от SHA-256 байтов файла.

`check` только читает. Успех `STRUCTURE_VALIDATED` означает совпадение структуры, хешей и покрытия; `semantic_review=NOT_EVALUATED_BY_SCRIPT` сохраняется намеренно. Временные метки в источниках неизменны, но скрипт не устанавливает связь с видео и не доказывает смысловую корректность диапазона, указанного редактором.

## Сопровождающий отчёт и реестр решений

`text-review.md` относится к конкретной версии текста и содержит:

- абсолютные пути и SHA-256 `lecture-text.json`, `lecture-text.md`, `source-blocks.json`, `source-manifest.json`, а также вычисленный `content_hash` лекции;
- основу и охват проверки: прочитанные источники, сопоставленные диапазоны/ID, метод, фактически выполненная смысловая сверка и её ограничения;
- сравнение объёмов и адресный разбор необъяснённого уплотнения по редакторским правилам;
- открытые вопросы и реестр решений с историей;
- отдельные результаты проверки структуры, смысловой самопроверки, независимого ревью и пользовательского решения. Невыполненная проверка отмечается явно.

Для записи реестра нужны устойчивый ID замечания, источник/locator и цитата, целевые ID и слой, исходный и предложенный текст, основание, решение и факт исполнения. Решение принимает одно из значений «предложено», «исправить», «оставить по решению пользователя». Исполнение фиксируется отдельно: не выполнено, внесено или сохранение проверено, с версией и результатом адресной сверки. Для пользовательского решения укажи точную формулировку и доступный адрес сообщения либо дату; недоступный идентификатор не выдумывай.

При новой версии перенеси действующие решения, сохрани историю и сопоставь адреса при изменении структуры. Для «оставить» проверь соответствующие фрагменты; для «исправить» — разрешённую замену и сохранность прежних решений. Отсутствие замечаний запиши явно. Читаемая история хранит весь контекст; проверяемую часть реестра оформи по [package-checks.md](package-checks.md). Пустой список решений допустим, если его подтверждает фактическая история.

## Передача на PDF

Передай полный `lecture-text.json`, `source-blocks.json`, `lecture-text.md`, `source-manifest.json`, `text-review.md`, `text-review.json` и результат `check-package`. Получатель сверяет версии и хеши, открытые вопросы и применимость решений к выбранному тексту; технический успех помощника этого не заменяет. Подписи и размещение ещё не существующего PDF остаются предложениями следующему этапу, если пользователь их отдельно не разрешил.

JSON — основное представление; Markdown — читаемая копия. Если пользователь явно выбрал отдельно отредактированный Markdown, это новый явно указанный вход: зафиксируй его хеш и перенеси применимые решения с новой адресной привязкой, не выдавая документ за прежний JSON. При отсутствии исходных материалов PDF-навык сможет проверить сохранение выбранного текста, но не полноту относительно отсутствующего транскрипта.
