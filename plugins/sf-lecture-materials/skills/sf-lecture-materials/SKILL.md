# SF Lecture Materials: полный цикл

Этот общий вход запускает только **полный цикл**: от материалов лекции до PDF-кандидата по Golden Gate. Он не предлагает упрощенные варианты и не заменяет явно выбранный специализированный навык.

Есть ровно два режима работы:

1. **Полный цикл через этот навык.** Материалы → принятый образец редактуры → полный LectureText → фактчек → решения человека → новая выбранная редакция → PDF-кандидат и QA.
2. **Прямой выбранный навык.** Пользователь явно вызывает \`$sf-transcript-to-lecture\`, \`$sf-fact-check\` или \`$sf-lecture-to-golden-pdf\`. Такой запуск остается в границах выбранного навыка и не запускает другие этапы автоматически.

## Прием материалов

1. Если материалов нет, попроси прикрепить транскрипт или папку по [сценарию первого сообщения](references/startup.md). Не требуй путь по умолчанию.
2. Если материалы есть, проверь только доступность, состав, роли файлов, извлекаемость текста, порядок частей и дубли. Полное чтение выполняется на текстовом этапе.
3. Сообщи последовательность полного цикла и его содержательные gate: принятие редакторского образца, решения по фактам и ручная приемка PDF. Повторно не спрашивай о тех же уже выбранных этапах.
4. Не начинай распознавание видео, установку зависимостей, публикацию, передачу файлов или работу подагентов только потому, что выбран полный цикл.

## Полный цикл

1. **Лекционный текст.** Используй [sf-transcript-to-lecture](../sf-transcript-to-lecture/SKILL.md). До массовой переработки покажи одну небольшую содержательную подтему. После принятия образца подготовь полный LectureText и его проверяемый текстовый комплект. Сохраняй смысл, примеры, числа, условия, оговорки и порядок источника; исправляй только однозначные языковые и ASR-ошибки.
2. **Фактчек.** На зафиксированном полном LectureText используй [sf-fact-check](../sf-fact-check/SKILL.md). Его полный результат — \`fact-check.json\`; в чат попадают только реальные ошибки и оговорки, меняющие учебный смысл, по [правилам предъявления](../sf-fact-check/references/human-review.md).
3. **Решения.** Человек решает только адресные actionable-пункты: \`FC-ID — исправить / оставить / перепроверить\`. Вносить правку можно лишь после решения \`исправить\`; решение \`оставить\` не меняет фактический статус claim; \`перепроверить\` сохраняет блокировку.
4. **Новая редакция и gate.** Для примененной правки создай новую версию LectureText. Перед PDF сформируй и проверь [full-cycle handoff 1.0.0](references/full-cycle-handoff-1.0.0.md). Он требует: отсутствие pending/recheck, новую целевую версию для всех \`correct\`, записанное \`keep\` и полное покрытие либо явно зафиксированное принятие ограничения.
5. **PDF.** Только после успешного handoff используй [sf-lecture-to-golden-pdf](../sf-lecture-to-golden-pdf/SKILL.md) с \`workflow.mode="full_cycle"\`. Candidate Manifest 2.1 связывает выбранный LectureText и успешный handoff. PDF-кандидат проходит технические и визуальные проверки, но становится принятым только после отдельного решения человека.

Если в полном фактчеке нет actionable-пунктов и coverage complete, дополнительных решений не требуется: handoff фиксирует отсутствие блокирующих решений и цикл продолжается. Если coverage partial или есть \`not_checked\`, PDF возможен только после явного принятия человеком точно описанного ограничения; без него gate блокирует выпуск.

## Прямой выбранный навык

- \`$sf-transcript-to-lecture\` создает или редактирует учебный текст и завершает свою работу текстовым результатом.
- \`$sf-fact-check\` проводит проверку, выдает отчет и принимает/применяет решения в собственной границе; сам по себе он не запускает PDF.
- \`$sf-lecture-to-golden-pdf\` создает PDF из явно выбранного готового текста. В этом режиме \`workflow.mode="direct_skill"\`; фактчек не подразумевается и не подменяется фиктивным отчетом.

Прямой режим PDF должен быть явно назван пользователем. Он не получает статус полного цикла и не заявляет прохождение фактчека.

## Границы результата

Технический валидатор сверяет файлы, хеши, записи решений и механические свойства PDF. Он не удостоверяет истинность источников, самостоятельность решения человека, смысловую полноту, визуальную уместность или ручную приемку. Новая версия текста или PDF требует новых связанных записей и проверок; исходники сохраняются.
