# Проверка утверждений по доказательным источникам

Проверь содержательные утверждения предоставленного текста, выходя за данные лекции. Результат — отдельный `fact-check.json` и читаемый нумерованный список замечаний в чате. Сохраняй исходный текст; исправления выполняются только после решения человека по предъявленным пунктам.

Этот навык подходит для обычного текста и LectureText JSON. Он применяется при запросе фактологической проверки, самостоятельно или в явно заказанном цикле перед PDF. Обычная редактура или вёрстка сами по себе не запускают внешнее исследование. Выбор навыка не разрешает делегирование, публикацию, покупки или установку инструментов.

## Зафиксировать материал и охват

1. Прочитай [правила доказательств](references/evidence-policy.md) и [формат отчёта и решений](references/report-contract.md).
2. Зафиксируй точный вход, SHA-256 его байтов и версию. Для LectureText 3.0.0 используй существующие ID и LaTeX; не меняй схему лекции. Для TXT/MD используй UTF-8. DOCX/PDF/сообщение сначала точно извлеки в локальный UTF-8 текст, сохрани хеш и адрес оригинала; проверь полноту извлечения. Не реконструируй нечитаемые формулы.
3. Прочитай весь заданный фрагмент. Выдели отдельные проверяемые утверждения, включая условия, оговорки, даты, определения, числа, гипотезы, теории и причинные выводы. Учебный пример ошибки, условие задачи, допущение модели и мнение не объявляй фактом о действительности. Зафиксируй исключения и непроверенные участки.
4. При отсутствии другой даты оцени актуальность на дату проверки, сохраняя исторический контекст лекции. Существенно недостающую страну, версию или условие уточни; не выбирай их незаметно.

## Проверить

- Для внешнего утверждения ищи подходящий независимый от лекции материал на релевантных языках. Используй доступный поиск, официальные сайты, академические базы и чтение PDF. Прочитай источник, а не только результат поиска.
- Доказательная основа строго ограничена нормативами, официальной документацией, академическими работами, официальными данными и первичными документами по правилам доказательств. Популярные пересказы, СМИ, блоги, Wikipedia и ответы моделей пригодны только для поиска первоисточника.
- Пересчитай вычисления и сохрани исходные значения, единицы, метод, условия и результат. Простая арифметика допускает самостоятельное воспроизводимое доказательство без искусственной ссылки. Помощник отчёта воспроизводит только ограниченную числовую арифметику; сложные вычисления или выводы опиши с реальной воспроизводимой процедурой и подходящими источниками.
- Для гипотез и теорий раздельно оцени точность атрибуции, степень подтверждения, наличие разногласий, допущения и пределы применимости. Не превращай публикацию гипотезы в доказательство её истинности, корреляцию — в причинность, норму — в описание фактического исполнения.
- Существенный или спорный вывод сопоставь по независимым основаниям. Не набирай число ссылок пересказами одной работы; не скрывай качественные противоречащие данные.
- Останавливай поиск, когда основание достаточно для узкого вывода либо дополнительные попытки не закрывают пробел. Для недоступного полного текста, неопределённых условий и недостаточных доказательств укажи конкретный предел. Не найдено подтверждение — не значит доказана ошибка.
- При недоступном внешнем поиске выполни допустимые локальные расчёты и оценку доступных доказательств, а внешние утверждения оставь непроверенными. Не выдавай память модели за внешнюю верификацию.

## Предъявить результат

Для каждого замечания покажи: постоянный ID, точную цитату и адрес, статус, доказательство с точным местом, объяснение расхождения, предел вывода и предлагаемую редакцию либо вопрос. Ссылка должна непосредственно поддерживать связанное с ней утверждение. Собственный вывод из нескольких источников обозначай и объясняй.

Сохрани все проверяемые утверждения в JSON, включая подтверждённые и непроверенные. В чате выведи отдельно замечания, затем краткий охват и пробелы; подтверждённые пункты не должны затруднять просмотр исправлений. Не заявляй исчерпывающую достоверность по числу найденных утверждений.

Запусти `python scripts/verify_fact_check.py --report <путь>` из папки навыка. Помощник читает файлы, проверяет байты, цитаты, формальные категории доказательств, арифметические записи и состояния решений. Он не ищет источники, не удостоверяет их подлинность и научную состоятельность, не пишет в лекцию и не доказывает согласие человека.

## Решения и продолжение

Дождись решения пользователя по замечаниям. Сохраняй точный комментарий и доступный адрес сообщения. «Исправить», «оставить», «перепроверить» — разные решения; отсутствие ответа не является согласием. Явное согласование всего предъявленного списка допустимо только для этой версии списка.

Применяй только согласованные исправления в новой версии текста. Учитывай изменённую пользователем формулировку. Если комментарий содержит новое проверяемое утверждение, исследуй его в пределах комментария и покажи обновлённое основание. Сохрани исходный результат проверки отдельно от редакторского решения: оставленная ошибка не становится подтверждённым фактом.

Для LectureText перенеси принятые решения с ID FC-* в существующий `text-review.json` по его контракту; сохрани исходные привязки и объясни внешнее основание новой редакции. Внешние источники не подменяют исходный транскрипт и его provenance. Проверь новую версию через `handoff.py`, затем затронутые утверждения и связанные выводы. Передай на PDF выбранную версию с явным перечнем оставшихся замечаний. Не блокируй самостоятельную вёрстку требованием фактчекинга, которого пользователь не заказывал.

Каждый раунд сохраняется отдельно; при повторном решении по тому же входу используй `--previous-report`. После изменения байтов входа нужен новый отчёт с новой проверкой адресов. По умолчанию один проход проверки и передача человеку; повторная работа ограничена его комментарием, без автоматических циклов «пока всё не подтвердится».
