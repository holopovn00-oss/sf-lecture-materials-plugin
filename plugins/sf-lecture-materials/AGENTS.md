# Правила SF Lecture Materials

Область действия: только работа с плагином **SF Lecture Materials** и его навыками. Это не общие инструкции репозитория, других плагинов или пользователя.

- Перед подготовкой лекции прочитай [правила композиции и пояснений](references/lecture-quality.md). Если рядом существует `LOCAL_MEMORY.md`, прочитай его как локальные предпочтения только этого плагина. Текущий запрос пользователя имеет приоритет.
- Объединяй связанные короткие фрагменты в законченные учебные темы. Сохраняй исходные блоки, смысловой порядок, условия, числа, формулы и привязки. Не объединяй разные темы исключительно ради сокращения числа страниц.
- Рассматривай чистые и аннотированные варианты исходных слайдов. Сохраняй полезные рукописные объяснения. Ошибочную запись разбирай согласованным учебным пояснением и правильной формулой в тексте; служебные сообщения об исправлении не печатай.
- Новые пояснения и схемы оформляй на текстовом/композиционном этапе в пределах разрешения пользователя, отдельно от дословного материала преподавателя. Проверь направление переноса стоимости, единицы ставки, число периодов, даты платежей и результат.
- В PDF показывай таймкоды `чч:мм:сс`, отбрасывая миллисекунды. Исходные временные привязки сохраняй точно. Общий диапазон допустим только для соседних блоков одного источника в исходном порядке.
- Перед выпуском проверь все страницы: короткие остатки, необоснованные пустоты, отделенные формулы и пояснения, читаемость слайдов. Сначала исправляй композицию и допустимые переносы. Не заполняй страницы повторениями и не уменьшай нормативный шрифт.
- Сохраняй проверки Golden Gate, фактчека и текста. Автоматический успех не заменяет визуальную проверку и приемку пользователем.
- Работа над лекцией сама по себе не разрешает изменения установленного плагина, памяти или публикацию в GitHub. Учитывай уже данное явное разрешение; не спрашивай повторно о согласованном действии.

`LOCAL_MEMORY.md` — обычный локальный файл, а не глобальная или автоматически гарантированная память Codex. Не записывай эти предпочтения в глобальные инструкции. Не публикуй локальный файл вместе со спецификацией без отдельного разрешения.


## Уточнение источников (21.09.2026)

Перед таймкодом указывай «Видео 1», «Видео 2» и т. д. согласно установленному соответствию транскрипта и записи. Время остается локальным для каждого видео; длительности частей не складываются. Нумерацию и основание фиксируй в `composition.time_sources`: `source_uri`, `label`, `basis`. Карта обязательна и для единственного временного источника: метка «Видео 1» печатается только после подтверждения соответствия. При отсутствии карты сначала установи соответствие по материалам; не угадывай его по совпавшей минуте. Для текста без временных привязок карта не нужна.

Подпись: Источник → Слайд № → Тема. Имя источника показывай без расширения файла, в том числе при переносах. Пустые поля допустимы по явному указанию пользователя. Готовые конспекты не являются источниками изображений. Служебные сообщения и FC-ID остаются только в рабочих отчётах.

## Источники и выпуск — 22.09.2026

По умолчанию используй исходные презентации, видео и другие визуальные материалы папки лекции. Отдельно разрешенная пользователем авторская схема имеет происхождение authored и не считается исходным слайдом. Транскрипты служат тексту и таймкодам. Готовые конспекты и ранее созданные PDF исключаются из визуальных источников, даже внутри этой папки. При ограничении исходными материалами не создавай заменяющие их авторские схемы.

Проверяй каждый визуал на фото/окно лектора. Выбирай исходный слайд без окна или извлекай область слайда, сохраняя весь учебный материал. Если исключение перекрывающего фото повредит формулу, ищи другой кадр; не дорисовывай формулу. Сохраняй оригинал, область и метод извлечения.

Общий рендерер и валидатор используют scripts/visual_policy.py. Для origin=original (значение по умолчанию) нужны source_root — абсолютная папка, source_inventory — список path/sha256/role с ролью original_visual, source и source_page либо pts_seconds/source_locator. Сверяй реестр с предоставленными оригиналами, не определяй происхождение по расширению. Для origin=authored нужны authoring.authorization — явное разрешение пользователя, authoring.basis — проверенное содержательное основание, text_block_ids — связанные блоки; source и image ссылаются на один созданный файл с его SHA-256. Подпись начинается с «Авторская схема»; такой файл не выдается за original_visual и не требует фиктивного исходного слайда. Для всех визуалов нужны lecturer_photo_review (absent/excluded) и extraction при исключении фото. Для пустой подписи оригинала запиши blank_caption_authorization. Записи о разрешении и проверке не являются независимым доказательством: агент сверяет их с реальным решением и материалами.

Перед выдачей просматривай все страницы; проверяй весь извлеченный текст на служебные фразы и FC-ID. Расширения убираются и проверяются только в явно обозначенном имени источника подписи: «Источник: имя», до разделителя → либо следующего поля «Слайд №:»/«Тема:». Перенесенные строки имени тоже проверяются. В учебном тексте, коде, примерах и поле «Тема:» расширения сохраняются. Приёмка относится только к предъявленному хешу. По прямому указанию заменить конспект выполняй COPY с заменой именно согласованного файла, сверяй SHA-256 и сохраняй accepted-manifest. Без указания не перезаписывай существующий файл.
