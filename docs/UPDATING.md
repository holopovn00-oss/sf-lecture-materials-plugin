# Обновление SF Lecture Materials на локальных машинах

Целевая версия: **0.4.1**, фиксированный Git-тег **v0.4.1**. Репозиторий: [sf-lecture-materials-plugin](https://github.com/holopovn00-oss/sf-lecture-materials-plugin). Выполняйте обновление отдельно на каждой машине.

Для одинаковой версии на нескольких компьютерах используйте тег v0.4.1. Обновление источника main получает текущую основную ветку, которая со временем может содержать более новую версию.

## 1. Проверить Codex и существующую установку

Откройте PowerShell. Найдите исполняемый файл Codex и проверьте его:

~~~powershell
Get-Command codex -All | Select-Object Source
codex --version
codex plugin --help
codex plugin list --json
codex plugin marketplace list --json
~~~

В списке ищите `sf-lecture-materials@sf-lecture-materials`: поля `version`, `installed`, `enabled`; источник marketplace должен соответствовать указанному репозиторию. Сохраните номер прежней версии и выбранный источник/ветку. Для точного возврата к произвольной локальной доработке заранее сохраните её отдельно.

Далее в примерах `codex` означает проверенный исполняемый файл. Если в PATH несколько Codex, запускайте нужный по полному пути:

~~~powershell
$CodexExe = 'C:/полный/путь/к/codex.exe'
& $CodexExe --version
& $CodexExe plugin list --json
~~~

В таком случае заменяйте `codex` в следующих командах на `& $CodexExe`. Это пример выбора пути, а не готовый путь к вашей машине.

Команды и чтение установленного Git marketplace проверены с **Codex CLI 0.153.4**. Минимальная совместимая версия не определена. Если CLI не знает `plugin` или не читает конфигурацию, сначала используйте совместимый CLI текущего приложения. В проверенной Windows-среде старый CLI 0.147.0 выдавал `invalid type: map, expected a boolean` для новой настройки features, а 0.153.4 успешно читал ту же конфигурацию. Ошибка не означает, что плагин не установлен. Не удаляйте настройки и кэши, чтобы скрыть несовместимость.

## 2. Выбрать способ обновления

### Закрепить 0.4.1 на всех машинах

Завершите активные работы с плагином. Если marketplace SF уже зарегистрирован с другой веткой, коммитом или локальным источником, сначала удалите **только его регистрацию и snapshot** штатной командой:

~~~powershell
codex plugin marketplace remove sf-lecture-materials
~~~

Этот шаг нужен только при существующей регистрации. Если команда сообщает об управляемом источнике или другой конфигурации, остановитесь и следуйте указанному месту настройки; не удаляйте директории вручную. Все локальные доработки плагина до смены источника должны быть сохранены отдельно.

Подключите опубликованный тег и установите плагин:

~~~powershell
codex plugin marketplace add holopovn00-oss/sf-lecture-materials-plugin --ref v0.4.1
~~~

После успешного завершения:

~~~powershell
codex plugin add sf-lecture-materials@sf-lecture-materials --json
~~~

Проверяйте успех каждой команды до перехода к следующей. Повторное `marketplace add` с другим ref может встретить конфликт существующего источника; это причина использовать явную смену регистрации, а не редактировать marketplace.json или config.toml вручную. Установка фиксированного тега не требует подписи версии вида `+codex...`: такая подпись предназначена для локальной разработки без смены базовой версии.

### Обновить уже подключённый Git marketplace из main

Если источник уже отслеживает main:

~~~powershell
codex plugin marketplace upgrade sf-lecture-materials --json
~~~

После успешного обновления snapshot:

~~~powershell
codex plugin add sf-lecture-materials@sf-lecture-materials --json
~~~

`upgrade` без имени обновляет все Git marketplaces, поэтому здесь имя обязательно. Команда обновляет выбранную в конфигурации ветку/ref; закреплённый тег не превращается автоматически в main. Для перехода с тега на main примените процедуру смены регистрации выше, указав `--ref main`.

Если SF marketplace ещё не подключён, сначала:

~~~powershell
codex plugin marketplace add holopovn00-oss/sf-lecture-materials-plugin --ref main
~~~

Затем выполните `plugin add`.

Локальный marketplace, указывающий на собственную папку разработки, не обновляется этой Git-командой. Сначала определите, нужны ли его локальные изменения. Для перехода на официальный репозиторий используйте смену регистрации; не подменяйте локальные файлы кэшем Git.

## 3. Подтвердить установленную версию

~~~powershell
codex plugin list --json
~~~

Ожидается запись `sf-lecture-materials@sf-lecture-materials`, `version: "0.4.1"`, `installed: true`, `enabled: true`. При обновлении из main сверяйте номер с текущим manifest репозитория; main может стать новее 0.4.1.

Откройте **новую задачу Codex**, выберите SF Lecture Materials и убедитесь, что доступны четыре навыка:

1. `sf-lecture-materials` — общий вход, приём материалов и выбранная последовательность.
2. `sf-transcript-to-lecture` — лекционный текст в JSON.
3. `sf-fact-check` — отдельные фактологические замечания с доказательствами.
4. `sf-lecture-to-golden-pdf` — PDF SF Education.

Если новая задача ещё показывает прежний набор, перезапустите приложение и повторите проверку версии. Не судите об обновлении по старой открытой задаче: в ней могли остаться ранее загруженные инструкции. Старый самостоятельный навык `sf-lecture-materials` и общий вход плагина — разные установки. Если самостоятельный навык требует DOCX и конфликтует с JSON-процессом, сохраните его папку целиком вне каталогов обнаружения навыков и уберите старую копию из активного каталога. Делайте это только для проверенной устаревшей копии после успешной установки новой версии. Не перезаписывайте локальные доработки и не правьте кэш плагина вручную.

Для проверки запуска выберите плагин в новой задаче без файлов. Ожидается просьба добавить материалы. Передав транскрипт без указания результата, получите три варианта; готовую лекцию — варианты фактчека/PDF. При явном выборе «лекционный материал с фактчеком, без PDF» следующая точка решения — образец, а не повторный выбор режима. Такой контроль не заменяет проверку конкретной лекции.

Для небольшого контроля фактчека передайте текст:

> В Python 3.14 round(2.5) возвращает 3. Проверь это через sf-fact-check по официальной документации, предложи исправление отдельным пунктом и дождись моего решения.

Ожидается замечание с точной цитатой, прочитанной документацией round, объяснением округления к чётному и предложением результата 2; исходный текст остаётся неизменным. Если доступа к документации нет, скилл должен явно записать ограничение. Этот пример проверяет один сценарий, а не всю фактологическую компетентность.

## 4. Зависимости

- **Текст и проверка отчётов:** Python 3.11+, стандартная библиотека.
- **Внешняя проверка фактов:** доступные в Codex поиск и чтение официальных/академических источников. Отдельный платный коннектор или MCP не обязателен. Сетевые ограничения отражаются в отчёте.
- **PDF:** PyMuPDF, Pillow, ReportLab; список находится в [requirements.txt](../requirements.txt).
- **Формулы:** Tectonic и подготовленный кэш нужных TeX-ресурсов. В математических проверках задаются `SF_TECTONIC` и `SF_TECTONIC_CACHE`. Полная установка TeX не обязательна.
- **Визуальный просмотр PDF:** Poppler / pdftoppm.

Плагин не устанавливает эти зависимости на все машины автоматически. Сначала проверьте доступный runtime в Codex. Установку недостающих Python-библиотек выполняйте в выбранном окружении из requirements.txt; системное Python-окружение не требуется менять. Подготовка Tectonic описана в [проверках PDF](../plugins/sf-lecture-materials/skills/sf-lecture-to-golden-pdf/references/automated-checks.md).

## 5. Вернуться к предыдущей версии

Для возврата к предыдущему состоянию **0.4.0** используйте тег `v0.4.0` (коммит `4a8081f538cea7a8f7e8ddbb745698f101665b04`). Эта версия уже содержит общий вход и три специализированных навыка, но manifest ресурсов ещё указывает 0.3.0. Возврат не восстанавливает старый самостоятельный DOCX-навык автоматически.

Завершите активную работу, затем выполните по одной команде, проверяя успех:

~~~powershell
codex plugin marketplace remove sf-lecture-materials
codex plugin marketplace add holopovn00-oss/sf-lecture-materials-plugin --ref v0.4.0
codex plugin add sf-lecture-materials@sf-lecture-materials --json
codex plugin list --json
~~~

Должна отображаться версия 0.4.0. После этого откройте новую задачу. Для возвращения на 0.4.1 повторите закрепление тега.

Исходные лекции и результаты храните в собственных папках задач, а не внутри установленного плагина или его snapshot. Смена версии плагина не мигрирует существующие JSON/PDF; каждый документ сохраняет свою версию и хеши.

## Основания и границы проверки инструкции

Синтаксис проверен по `--help` фактически доступного Codex CLI 0.153.4, установленный источник — через `plugin list --json` и `plugin marketplace list --json`. Сведения о локальном обновлении относятся к конкретной машине и фиксируются отдельно после выполнения команд. Инструкция и автоматические проверки не доказывают загрузку новых навыков в ранее открытой задаче.

Поведение обновления и конфликта источника сверено с официальным кодом OpenAI: [marketplace_cmd.rs](https://github.com/openai/codex/blob/main/codex-rs/cli/src/marketplace_cmd.rs), [marketplace_add.rs](https://github.com/openai/codex/blob/main/codex-rs/core-plugins/src/marketplace_add.rs), [загрузка ref](https://github.com/openai/codex/blob/main/codex-rs/core-plugins/src/marketplace_add/install.rs), [удаление регистрации/snapshot](https://github.com/openai/codex/blob/main/codex-rs/core-plugins/src/marketplace_remove.rs), [plugin_cmd.rs](https://github.com/openai/codex/blob/main/codex-rs/cli/src/plugin_cmd.rs). Код main может обновляться; фактический `--help` вашей версии имеет приоритет для синтаксиса.

Общая документация продукта: [OpenAI — Plugins](https://learn.chatgpt.com/docs/plugins). Поведение контрольного примера: [Python 3.14 — round](https://docs.python.org/3.14/library/functions.html#round).
